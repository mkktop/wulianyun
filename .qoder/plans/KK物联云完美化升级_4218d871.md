# KK物联云完美化升级方案

## 总览

基于对项目代码的逐行分析和天翼CTWing/中移OneNET/有人云三大平台对标，制定 6 阶段升级方案。预期完成后支撑设备规模从 500-1000 台提升到 **10000+ 台**，功能对齐主流平台 90%+ 能力。

---

## 阶段一：性能基础（最高优先级，不改变架构）

> 目标：消除热路径瓶颈，支撑能力提升 10 倍。无需新依赖。

### 1.1 DB 连接池配置
- **文件**: `server/internal/repository/db.go`, `server/internal/config/config.go`, `server/configs/config.yaml`
- **改动**: db.go 第 28 行后添加 `sqlDB.SetMaxOpenConns(50)`, `SetMaxIdleConns(10)`, `SetConnMaxLifetime(30min)`, `SetConnMaxIdleTime(10min)`
- **config.go**: Database 新增 `MaxOpenConns/MaxIdleConns/ConnMaxLifetime/ConnMaxIdleTime`；Redis 新增 `PoolSize/MinIdleConns`
- **config.yaml**: 添加对应配置项

### 1.2 TimescaleDB 数据保留与压缩
- **文件**: `server/internal/repository/db.go`
- **改动**: 第 48 行 hypertable 创建后追加 `add_retention_policy('telemetries', INTERVAL '30 days')` 和 `add_compression_policy('telemetries', INTERVAL '7 days')` + `compress_segmentby = 'device_id'`
- **config.go**: Database 新增 `RetentionDays/CompressAfterDays`

### 1.3 Redis Lua 原子合并最新值
- **文件**: `server/internal/service/ingest.go`
- **改动**: 第 129-148 行替换为 Redis Lua 脚本，将 GET+合并+SET 两次 RTT 降为一次原子操作
- **新增**: `mergeLatestScript` 变量，使用 cjson 在 Redis 内完成合并

### 1.4 设备信息内存缓存
- **新增文件**: `server/internal/service/device_cache.go`
- **结构**: `sync.Map`，key=`productKey\x00deviceName`，TTL=5min
- **修改**: `ingest.go` FindDevice 函数先查缓存；`api/device.go` CRUD 后调用 `InvalidateDeviceCache()`
- **失效触发**: UpdateDevice/DeleteDevice/动态注册/状态变更后主动失效

### 1.5 规则表缓存
- **文件**: `server/internal/rule/engine.go`
- **结构**: `ruleCache map[uint][]model.Rule`（userID→规则列表），TTL=30s
- **修改**: `EvalTelemetry` 第 25-29 行替换为 `loadRulesForUser(userID)`，内存中按 product_id/device_id 过滤
- **失效触发**: `api/rule.go` CRUD 后调用 `InvalidateRuleCache()`

### 1.6 Shadow 内存缓存
- **新增文件**: `server/internal/service/shadow_cache.go`
- **结构**: `sync.Map`（deviceID→shadowCacheEntry），dirty 标记 + 5s 定时 flush
- **修改**: `shadow.go` GetShadow/mergeShadowReported 走缓存；UpdateShadowDesired 立即刷盘
- **一致性**: 单条影子通过 entry.mu 保证并发安全，崩溃最多丢 5s 数据，下次上行自动修复

### 1.7 批量写入 Telemetry
- **新增文件**: `server/internal/service/telemetry_buffer.go`
- **结构**: `TelemetryBuffer` 含 items 切片 + maxBatch(100) + flushInterval(1s)
- **机制**: 后台 goroutine 定时 flush；满 maxBatch 即时 flush；GORM `Create(&items)` 自动生成批量 INSERT
- **修改**: `ingest.go` 第 122-127 行改用 `AppendTelemetry(t)`
- **生命周期**: `main.go` 初始化 + shutdown hook 最后一次 flush

### 1.8 WebSocket Hub 按用户分桶
- **文件**: `server/internal/ws/hub.go`
- **改动**: `clients` 从 `map[*Client]bool` 改为 `map[uint]map[*Client]bool`（userID→set）
- **修改**: Serve 注册按 userID 分桶；push 直接定位用户桶，O(用户连接数) 替代 O(总连接数)

### 1.9 轮询引擎优化
- **文件**: `server/internal/poller/poller.go`
- **点位缓存**: `sync.Map`（productID_groupID→点位表），TTL=5min，API 修改后主动失效
- **随机延迟**: `runGroup` 首次执行前加 `rand.Int63n(interval)` jitter，错开雷群
- **并发限制**: `pollSemaphore chan struct{}` 信号量，默认 50 并发，超时 3s 跳过

### 1.10 TCP 连接速率限制
- **文件**: `server/internal/gateway/tcp.go`
- **IP 连接数**: `sync.Map` 存 `*int64` atomic 计数器，超限（默认 10）拒绝
- **频率限制**: 令牌桶算法，Accept 循环中检查，超限直接 Close
- **config.go**: Gateway 新增 `MaxConnsPerIP/ConnRateLimit/ConnRateBurst`

### 1.11 main.go 初始化编排
- **文件**: `server/cmd/server/main.go`
- **顺序**: `repository.Init()` → `service.InitTelemetryBuffer()` → `service.InitShadowCache()` → `poller.InitPollerSemaphore()`
- **Shutdown**: 逆序关闭各组件

## 阶段二：MQTT/TCP 协议增强

> 目标：对齐 OneNET/CTWing 协议能力，实现可靠的请求-响应模式。

### 2.1 请求-响应关联
- **新增模型**: `model/ops.go` 新增 `CommandRequest`（messageId/deviceId/method/payload/status/response/timeoutMs）
- **修改**: `api/shadow.go` InvokeService/SetDeviceProperty 生成 messageId，下行 payload 增加 messageId 字段
- **新增**: `mqtt/client.go` 暴露 `Client()` 方法 + 新增 `SubscribeReply()` 订阅 `thing/up/+/+/reply`
- **新增**: `service/ingest.go` 新增 `HandleDeviceReply()` 处理应答，按 messageId 匹配等待 channel
- **修改**: `api/emqx.go` EmqxACL 放行 reply 主题
- **API 变更**: 服务调用/属性设置响应增加 `{messageId, status: "pending"|"acked"|"timeout"}`

### 2.2 物模型运行时强校验
- **新增文件**: `server/internal/service/validate.go`
- **函数**: `ValidateTelemetry(productID, data)` — 按 TSL properties 逐字段校验类型/范围/枚举
- **修改**: `model/model.go` Telemetry 新增 `Valid bool` + `ValidationErrors jsonb`
- **调用点**: `ingest.go` HandleTelemetry 入库前校验，失败标记但不丢弃
- **扩展**: `handleEventReport` 校验 identifier 是否在 TSL events 中定义；`InvokeService` 校验入参

### 2.3 影子 delta 推送
- **文件**: `server/internal/service/shadow.go`
- **修改**: `UpdateShadowDesired` 计算 old vs new delta，仅推送差异部分
- **下行格式**: `{"method":"property.set","params":{差异},"delta":true,"ts":...}`

### 2.4 TLS 支持
- **文件**: `server/internal/config/config.go`, `server/internal/mqtt/client.go`, `server/internal/gateway/tcp.go`, `server/configs/config.yaml`
- **MQTT TLS**: config 新增 `mqtt.tls` 段（enabled/ca_cert/client_cert/client_key），Start() 构造 tls.Config
- **TCP TLS**: config 新增 `gateway.tls` 段（enabled/cert_file/key_file），Start() 用 `tls.Listen()` 替代 `net.Listen()`

### 2.5 HTTP 接入协议
- **新增文件**: `server/internal/api/device_http.go`
- **API**: `POST /api/v1/http/telemetry`（公开接口，不走 JWT）
- **认证**: `X-Device-Token: Base64(pk:dn:secret)` header
- **逻辑**: 解码 Token → FindDeviceForAuth 验证 → HandleTelemetry → 返回 ok
- **路由**: `router.go` 在 v1 组注册

## 阶段三：规则引擎升级

> 目标：从基础单条件升级为复合条件+自动恢复+多目标转发。

### 3.1 复合条件
- **文件**: `server/internal/rule/engine.go`, `server/internal/model/thing.go`
- **模型变更**: Rule.Condition 支持嵌套格式 `{"logic":"and","conditions":[...]}`，向后兼容旧单条件
- **新增**: `evalCondition(cond, data)` 递归评估函数，检测 `logic` 字段决定递归/叶子
- **限制**: 最大嵌套 3 层，最大条件数 20

### 3.2 告警自动恢复
- **文件**: `server/internal/rule/engine.go`
- **修改**: `evalAlarmRule` 条件不满足时查询 firing 告警 → 自动 resolve + 发送恢复通知
- **恢复通知**: Webhook 推送 `type: "alarm_resolve"` + WebSocket 推送

### 3.3 数据转发扩展
- **新增文件**: `server/internal/rule/forward.go`
- **新增目标**: Kafka（`github.com/IBM/sarama`）+ MQTT 桥接（独立 paho client）
- **模型变更**: Rule.Action 支持 `{"type":"kafka","brokers":[...],"topic":"..."}` 和 `{"type":"mqtt_bridge","broker":"...","topic":"..."}`
- **容错**: 连接失败不影响主流程，异步 goroutine 执行

### 3.4 Webhook 重试
- **文件**: `server/internal/rule/engine.go`
- **修改**: `postJSON` 改为 `postJSONWithRetry`，指数退避（1s→2s→4s→...→30s cap）
- **模型变更**: Rule 新增 `RetryCount int`（默认 3）
- **异步化**: 重试循环在 goroutine 内执行，不阻塞规则评估

## 阶段四：开发者调试工具

> 目标：补齐最大短板，对标 OneNET/CTWing 开发者体验。

### 4.1 Web 端设备模拟器
- **新增后端**: `server/internal/api/simulator.go`
  - `POST /simulator/connect` — 创建模拟会话，调用 HandleDeviceStatus 模拟上线
  - `POST /simulator/publish` — 模拟设备上行，调用 HandleTelemetry
  - `POST /simulator/disconnect` — 断开模拟会话
  - `GET /simulator/sessions` — 查询活跃会话
- **新增前端**: `web/src/views/DeviceSimulator.vue`
  - 产品/设备选择器 + 连接状态灯 + 遥测上报 JSON 编辑器 + 事件上报表单 + 下行消息实时列表
- **路由**: `/tools/simulator`

### 4.2 在线 MQTT 调试台
- **新增后端**: `server/internal/api/mqtt_debug.go`
  - `GET /mqtt-debug/ws` — WebSocket 端点，后端代理 MQTT 发布/订阅
  - 前端发 JSON 指令 `{action:"subscribe"|"publish"|"unsubscribe", topic, payload, qos}`
  - 后端用内部 MQTT 客户端执行，订阅消息通过 WS 推前端
- **新增前端**: `web/src/views/MqttDebug.vue`
  - 发布区（topic + QoS + payload 编辑器）+ 订阅区 + 消息流实时滚动
- **路由**: `/tools/mqtt-debug`

### 4.3 消息轨迹追踪
- **新增模型**: `server/internal/model/trace.go` — `MessageTrace`（traceId/userId/deviceId/direction/topic/payload/stage/status/各阶段耗时/error）
- **处理阶段**: `received → decoded → stored → rule_evaluated → pushed`
- **核心修改**: `ingest.go` HandleTelemetry 入口生成 traceId，各步骤记录耗时，异步写入 trace 表
- **新增后端**: `server/internal/api/trace.go` — `GET /traces`（分页查询）+ `GET /traces/:traceId`（详情）
- **新增前端**: `web/src/views/MessageTraces.vue` — 搜索栏 + 列表 + 详情抽屉（时间线组件）
- **路由**: `/tools/traces`
- **保留策略**: 7 天自动清理

### 4.4 设备运行日志增强
- **新增模型**: `model/ops.go` — `DeviceLog`（deviceId/category/summary/payload/traceId）
- **类别**: connection / data_up / data_down / event / error
- **核心修改**: ingest.go/event.go/tcp.go 各入口异步写入 DeviceLog
- **新增后端**: `server/internal/api/device_log.go` — `GET /devices/:id/logs` + `GET /device-logs`
- **前端**: `DeviceDetail.vue` 新增"运行日志"Tab
- **保留**: 配置 `log.retention_days`（默认 30），启动时定时清理

### 4.5 API 在线调试（Swagger）
- **新增依赖**: `github.com/swaggo/swag`, `github.com/swaggo/gin-swagger`, `github.com/swaggo/files`
- **后端**: 各 handler 添加 swag 注释 → `swag init` → `main.go` 注册 `/swagger/*any`
- **前端**: 侧边栏"应用管理"下新增"API 文档"链接，新标签页打开 `/swagger/index.html`

## 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 批量写入崩溃丢数据 | 中 | shutdown hook flush；遥测允许少量丢失 |
| 影子缓存崩溃丢 5s 数据 | 中 | 最终一致，下次上行自动修复 |
| 消息轨迹写入量大 | 中 | 异步批量写入 + 7 天短期保留 + 可选开关 |
| MQTT 调试台安全性 | 高 | 严格限制 topic 范围 + 审计日志 |
| 请求-响应同步等待阻塞 | 中 | 10s 超时 + 异步模式备选 |
| NAT 后多设备共享 IP 被限 | 中 | 默认 10 足够；可配置调高 |
| Kafka 依赖引入体积大 | 低 | build tag 可选编译 |
| DB 迁移兼容性 | 中 | 新字段均有默认值 |

## 预期成果

完成后平台能力对标：
- **MQTT/TCP 接入**: 对齐 OneNET（请求-响应、TSL 校验、delta 推送、HTTP 接入、TLS）
- **开发者工具**: 对齐 CTWing/OneNET（模拟器、MQTT 调试、消息轨迹、运行日志、API 文档）
- **规则引擎**: 对齐 ThingsBoard（复合条件、自动恢复、多目标转发）
- **性能**: 从 500-1000 台提升到 **5000-10000+ 台**（批量写入+缓存+连接池优化）
- **差异化优势**: Modbus 工业级采集 + 私有化部署 + 完全自主可控
