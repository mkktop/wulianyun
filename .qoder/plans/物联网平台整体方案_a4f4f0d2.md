# 物联网平台整体方案（对标 OneNET / CTWing / 有人云）

## 方案总览

采用「模块化单体 + 独立接入组件」架构：Go 单体后端承载业务，EMQX 承载 MQTT 海量连接，自研 Go TCP 网关承载 DTU 透传，前端 Vue3 管理后台。后续任一模块可平滑拆为微服务。

```
设备侧                        平台侧                          应用侧
MQTT设备 ──► EMQX ──webhook/hook──►┐
DTU/透传 ──► TCP接入网关(Go) ──────►│  Go 单体后端(Gin)          Vue3 管理后台
HTTP设备 ──► HTTP接入API ─────────►│  ├─ 设备/产品/物模型        ├─ 设备管理
                                   │  ├─ 规则引擎/告警           ├─ 实时监控(WS)
                                   │  ├─ 数据服务/命令下发       └─ 可视化大屏
                                   │  └─ OpenAPI
                                   ▼
                    PostgreSQL(业务) + TimescaleDB(时序) + Redis(在线状态/缓存)
```

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端框架 | Go 1.22+ / Gin / GORM / Viper / Zap | 模块化单体 |
| MQTT 接入 | EMQX 5.x 开源版（Docker） | HTTP 认证钩子对接平台、Webhook/规则引擎转发上行数据 |
| TCP 透传接入 | 自研 Go TCP Server | 对标有人云 DTU 场景，注册包鉴权 + 心跳 + 透传 |
| 业务库 | PostgreSQL 16 | 用户/产品/设备/规则等 |
| 时序库 | TimescaleDB（PG 扩展） | 设备遥测数据，超表 + 自动压缩/保留策略，不额外增加组件 |
| 缓存 | Redis | 设备在线状态、令牌、下行命令队列 |
| 前端 | Vue3 + Vite + TypeScript + Element Plus + ECharts | 管理后台与大屏 |
| 实时推送 | WebSocket（gorilla/websocket） | 前端实时数据与告警 |
| 部署 | docker-compose（EMQX/PG/Redis），后端前端可容器化 | 单机即可跑通 |

## 核心功能模块

### 1. 账户与权限
- 用户注册/登录（JWT）、RBAC（管理员/普通用户）、多租户按 user_id 隔离数据。

### 2. 产品与物模型（TSL）
- 产品 = 一类设备的模板：接入协议（MQTT/TCP透传/HTTP）、数据格式（JSON/自定义脚本解析）。
- 物模型：属性（可读写、数据类型、单位、范围）、事件（告警/故障）、服务（命令），JSON 定义存库。

### 3. 设备管理
- 设备三元组（ProductKey/DeviceName/DeviceSecret）生成与鉴权；设备增删改查、批量导入。
- 生命周期：未激活/在线/离线/禁用；在线状态由 EMQX 事件 + Redis 维护。
- 设备影子（desired/reported），离线命令补发。

### 4. 设备接入
- MQTT：EMQX HTTP Auth 对接平台鉴权接口；约定主题规范 `$thing/up|down/{productKey}/{deviceName}`；EMQX 规则引擎经 Webhook 将上行消息、上下线事件推给后端。
- TCP 透传网关：注册包（携带设备凭证）→ 鉴权 → 心跳保活 → 数据透传；支持按产品配置的脚本（内嵌 Lua 或 JS 引擎 goja）把二进制报文解析为物模型 JSON。
- HTTP 上报：低频设备直接 POST 遥测。

### 5. 数据服务
- 遥测数据写入 TimescaleDB 超表（device_id, ts, 属性 JSONB）；最新值缓存 Redis。
- 查询 API：最新值、历史曲线（聚合降采样）、数据导出 CSV。

### 6. 规则引擎与告警
- 数据转发规则：条件匹配（产品/设备/属性表达式）→ 动作（HTTP 推送、转发 MQTT 主题、写库）。
- 告警规则：阈值/离线告警 → 告警记录 + 通知（站内 WebSocket、邮件、Webhook，短信留接口）。

### 7. 命令下发与控制
- 属性设置/服务调用 → 经 EMQX 发布到下行主题或 TCP 网关写连接；同步（等待回执超时）与异步两种模式。

### 8. 监控与可视化
- 平台概览：设备总数/在线数、今日消息量、告警统计。
- 设备详情：实时数据（WebSocket 推送）、历史曲线、事件日志、调试面板（模拟下发/查看原始报文）。
- 可视化大屏：ECharts 地图 + 关键指标。

### 9. OpenAPI
- 面向第三方应用的 REST API（AppKey/AppSecret 签名），覆盖设备 CRUD、数据查询、命令下发。

```

│  │  ├─ model/            # 实体与 DTO

   ├─ src/api/  src/stores/  src/router/
   └─ ...
```

## 分期实施

### 第一期：接入与管理 MVP（先做）
- docker-compose 基础设施；Go 工程骨架（配置/日志/JWT/统一响应）。
- 用户登录注册、产品管理、设备管理（三元组、状态）。
- EMQX 对接：设备鉴权、上下线事件、JSON 遥测上行入库。
- 数据查询 API + 前端：登录、概览、产品/设备列表、设备详情实时数据（WebSocket）与历史曲线。

### 第二期：物模型与规则
- 物模型定义与校验、设备影子、命令下发（属性设置/服务调用）。
- 规则引擎（转发 + 告警）、告警通知、告警中心页面。

### 第三期：透传与开放能力
- TCP 透传网关 + 脚本协议解析（对标有人云 DTU）。
- OpenAPI（AppKey 签名）、可视化大屏、数据导出、批量导入。

## 验证方式
- 用 MQTTX 模拟 MQTT 设备完成鉴权、上报、下发全链路。
- 用 netcat/自写脚本模拟 DTU 注册包与透传报文。
- 后端单元测试覆盖 service 层核心逻辑；前端手工联调验证。

## 假设与约定
- MVP 目标支撑万级设备连接（EMQX 单节点能力内），暂不做集群与 K8s。
- 短信/邮件通知第三期前仅留接口，默认 Webhook 通知。
- 开发环境需 Docker Desktop；若无法使用将退化为本地安装 PG/Redis + 内嵌 Go MQTT broker（mochi-mqtt）替代 EMQX。
