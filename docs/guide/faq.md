# 常见问题 FAQ

---

## 设备连接

**Q：MQTT 设备连不上（Connection Refused / Not Authorized）？**

按顺序检查：

1. 三元组是否正确：`Username = DeviceName`，`Password = DeviceSecret`（或 `tk:` 动态 Token）
2. `ClientID = {ProductID}{DeviceName}` **纯拼接、无分隔符**（前 12 字符为产品 ID）
3. 设备是否被**禁用**（禁用设备认证直接拒绝）；产品是否被删除
4. 一型一密动态注册：密码应为 `ProductSecret`，且设备名在产品内唯一
5. 仍失败时在 **开发工具 → 消息轨迹** 中查该设备的认证记录

**Q：TCP/DTU 设备注册后立即断开？**

- 注册包必须在连接后 **10 秒内**发送，格式为单行 `{productId},{deviceName},{secret}\n`（或产品配置的注册码）
- 鉴权成功回复 `OK\n`，失败回复 `ERR\n` 并断开
- 心跳帧必须符合产品组帧配置（delimiter 模式的自定义心跳要带定界符，如 `0D0A`）

**Q：HTTP 直传返回 401？**

`X-Device-Token` 为 `Base64(productId:deviceName:secret)`，且仅支持**固定 Secret**（不支持 `tk:` 动态 Token）。

## 数据上报

**Q：设备上报了，但实时数据里没有？**

常见原因：

1. **物模型校验失败**：属性未在产品功能定义中声明、或数值超限——数据仍写入历史（供回溯），但被拦在实时数据/影子/规则之外。到消息轨迹看 `validation_failed` 状态与具体原因
2. payload 里有系统键（`method`/`messageId`/`ts` 等），它们不是属性、会被自动剔除
3. 设备离线补发的时间戳超出合理窗口（见下一条）

**Q：断网补传的数据时间不对？**

平台以 payload 顶层的 `ts`（毫秒）为**设备采集时间**入库（合理窗口：服务器时间 -7 天 ~ +5 分钟，超出回退服务器时间）。DTU 断网缓存补传时请务必在报文中携带原始 `ts`。

**Q：历史曲线 24 小时以上变"稀"了？**

这是**预期行为**：查询范围超过 6 小时自动切换为时间桶聚合（默认取平均值，桶宽按范围自动取整），曲线左上角会标注聚合粒度。原始点查询上限 1 万行。开放接口可用 [`/devices/:id/history/agg`](/guide/api-reference) 自定义 `agg`（avg/min/max/sum/count）与 `interval`。

**Q：怎么导出历史数据？**

设备详情 → 历史曲线 → **导出**：选时间范围与参数，CSV 下载。单次最长 **31 天**。

## 下行与指令

**Q：下发的指令设备收不到？**

1. MQTT 设备必须**订阅** `thing/down/{productId}/{deviceName}`（QoS 1）
2. 设备需在线；离线写入的是**设备影子**（desired），上线后自动补发
3. TCP 设备注意：下行走的是设备当前 TCP 连接（多实例经 Redis 路由），连接断开即失败

**Q：指令一直是 pending？**

`pending → acked` 需要设备在 `thing/up/{pk}/{dn}/reply` 回应 `{messageId, code, data}`。超过指令超时（默认 10s）未应答，后台每分钟扫描一次置为 `timeout`。若设备确实回复了但仍 pending，检查 reply 里的 `messageId` 是否与下发一致。

**Q：属性设置了但设备没变？**

看设备详情「属性设置」区的期望状态标签：`期望 xx（未达成）` 表示 desired 已写入、等设备上报达到后自动清除；设备离线时属正常现象。

## 告警与规则

**Q：规则触发太频繁/太迟钝？**

调大**静默期**（默认 5 分钟：同一规则同一设备在静默期内的重复触发会被抑制）。阈值告警在条件不再满足时会**自动恢复**（firing → resolved）。

**Q：告警了但我不知道？**

平台通知渠道：**站内实时推送**（WebSocket，控制台右下角弹窗 + 告警中心）与 **Webhook**（POST 到你配置的 URL，指数退避重试）。短信/邮件/IM 机器人可通过 Webhook 对接 IM 机器人地址实现。离线告警由每分钟一次的巡检触发，最长有 1 分钟延迟。

## 安全与账号

**Q：修改密码后旧会话还有效吗？**

无效。改密（或管理员重置密码）后，该账号所有旧 token **立即失效**，需要重新登录。

**Q：一型一密的 ProductSecret 泄露了怎么办？**

ProductSecret 可冒充产品下任意设备动态注册。泄露后请立即在产品中重新生成（原 Secret 即刻失效），并排查异常设备。

**Q：OpenAPI 签名总返回 401？**

1. `X-Timestamp` 为**秒级** Unix 时间戳，与服务器时差须在 **±5 分钟**内
2. `X-Nonce` 一次性随机串（8-64 字符），**纳入签名串且不可重复使用**（防重放）
3. 签名串各段用 `\n` 连接，顺序为 `Method\nPathAndQuery\nhex(SHA256(Body))\nAppKey\nTimestamp\nNonce`，GET 请求 Body 哈希取空串的 SHA256
4. 完整算法与示例代码见 [OpenAPI](/guide/openapi)

## 其他

**Q：设备状态「未激活」是什么意思？**

设备创建后从未连接过平台。首次连接（任一协议）即转为在线/离线态。

**Q：设备时间与平台时区不一致会影响什么？**

平台内部统一毫秒时间戳存储、按浏览器时区展示。设备自带 `ts` 超出 ±窗口会被忽略（回退服务器时间），如需补传历史数据请校准设备时钟或检查上报的 `ts` 单位是否为毫秒。
