# OTA 下发增加 CRC32 + 严格按设备协议选路

## 目标
1. `ota.push` 下发报文新增 `crc32` 字段（与现有 SHA-256 并存，轻量快速校验）
2. 去掉 CreateOTATask 里无脑的 MQTT fallback，让 TCP 设备走 TCP、MQTT 设备走 EMQX（DownPublisher 内部已正确分流）

## 一、后端改动

### 1. `server/internal/model/ops.go` — Firmware 模型加字段
在 `Checksum` 后新增：
```go
CRC32  uint32   `gorm:"default:0" json:"crc32"`
```
GORM AutoMigrate 自动加列；旧固件值为 0，设备端按"0=不校验"处理。

### 2. `server/internal/api/ota.go`
**上传算 CRC32**（`CreateFirmware`，~line 117-126）：
- import `hash/crc32`
- 把 `io.TeeReader(file, hasher)` 改为同时喂两个 hasher：
  ```go
  sha := sha256.New()
  crc := crc32.NewIEEE()
  storage.Default.Put(ctx, key, io.TeeReader(file, io.MultiWriter(sha, crc)), header.Size)
  checksum = hex.EncodeToString(sha.Sum(nil))
  crc32Val := crc.Sum32()
  ```
- `fw.CRC32 = crc32Val`

**下发带 crc32**（`CreateOTATask`，~line 215-223）：
```go
otaPayload, _ := json.Marshal(map[string]interface{}{
    "method":  "ota.push",
    "version": fw.Version,
    "url":     fw.FileURL,
    "size":    fw.FileSize,
    "sha256":  fw.Checksum,
    "crc32":   fw.CRC32,
    "taskId":  task.ID,
    "ts":      time.Now().UnixMilli(),
})
```

**去掉 MQTT fallback**（~line 225-238）：
当前：
```go
if service.DownPublisher != nil {
    if err := service.DownPublisher(...); err == nil { successCount++; continue }
}
// fallback: 直接 MQTT
if err := mqtt.PublishDown(...); err == nil { successCount++ }
```
改为（保留 nil 兜底，去掉报错回退 MQTT）：
```go
if service.DownPublisher == nil {
    // 仅测试/未注入时兜底；生产已注入
    if err := mqtt.PublishDown(d.ProductKey, d.Name, otaPayload); err == nil {
        successCount++
    }
    continue
}
if err := service.DownPublisher(d.ProductKey, d.Name, otaPayload); err == nil {
    successCount++
}
```
语义：TCP 设备走 gateway/Redis fanout，MQTT 设备走 EMQX，失败（设备离线）如实计入失败，不再伪装成功。

## 二、前端改动
`web/src/views/OTA.vue`：在"校验值(SHA-256)"列旁加一列 CRC32（展示 `row.crc32`，0 显示为"—"）。轻量，1 处。

## 三、文档（3 处 ota.push 报文同步加 crc32 字段）
1. `docs/guide/ota.md`（canonical，§4.1 报文 + §2 上传响应表）
2. `docs/guide/downlink-shadow.md:147`
3. `docs/guide/mqtt.md:116`

字段说明统一为：
> `crc32` 无符号 32 位整数（IEEE），范围 0~4294967295。值为 0 表示该固件无 CRC32（旧固件），请仅校验 `sha256`；非 0 时建议先做 CRC32 快速校验，再做 SHA-256 完整性校验。

## 四、不做 / 已知限制
- **不改 Redis `PublishDown` 的零订阅者假成功**：这是预存行为（与本改动无关），离线 TCP 设备在多实例 Redis 模式下 `pushedCount` 仍可能虚高。本次不引入也不修，留作后续可选优化。
- **不改设备端**：CRC32 校验是设备固件职责，平台只负责下发正确值。
- **CRC32 用 IEEE 多项式**（`crc32.ChecksumIEEE`），与嵌入式固件最常见的 CRC32 约定一致。
